# 统一 Raw → HDF5 → LeRobot 78 维：实施与使用

日期：2026-10-28。以本文件的 **78 维、仅 mask 夹爪** 契约为准，之前的“删除夹爪后导出76维”方案已废止。76仅表示有效维数，不表示数组长度。

## 目录与编号

继续使用三个分开的目录，同一次采集从录制到导出始终使用同一个 episode 编号和 capture_id。以42号为例：

```text
/mnt/apex-data/apex_n_sharpa/data/
├── raw_data/apex_data/<task>/episode_00000042/
│   ├── manifest.json                         传输清单
│   └── payload/                              原始录制完整副本
│       ├── *.mcap、metadata.yaml
│       ├── video/...                         原相机文件
│       ├── capture_time.json
│       ├── capture_manifest.json
│       └── capture_completion.json
├── hdf5/<task>/hdf5_00000042.hdf5
└── lerobot/<task>/episode_00000042/
    ├── data/chunk-000/episode_000042.parquet
    └── meta/                                 info、统计、时间、capture和replay证据
```

LeRobot内部文件按v2.1模板至少补齐六位，外层补齐八位；数值编号均为42。Parquet的episode_index及episodes.jsonl也为42，不重新从0编号。同一任务内同编号绑定到不同capture_id时拒绝导入，不覆盖旧文件。

机器人录制时分配并持久化编号，文件名为episode_XXXXXXXX；用户录制名称另外保存为recording_label。失败录制已占用的编号不复用，允许编号有空缺。现有旧导入编号0、1、2保留；部署初始化next_index为3，后续分配也扫描机器人的已有编号目录。

旧episode_00000002没有改写。旧Raw目录包含MCAP、metadata和video等原始资料；其HDF5和LeRobot此前已经在各自的独立目录中，不是全部塞在Raw里面。旧数据没有真实双手流，不能补零后冒充新统一格式。

## 实施分工

1. **录制端**：机器人`/home/user/apex_record_sync/contract.py`负责一次分配编号、开始/停止事务、完成凭证；不改变原Record/Stop入口。新代码在下一次正常启动Teleop + Replay时加载。
2. **Raw导入**：`/home/descfly/apex_n_sharpa/src/import_unified.py`按记录的编号完整拷贝payload，核对COMPLETE、文件清单和SHA256，默认拒绝diagnostic，原子提交目录。
3. **Raw→HDF5**：在原身体转换器中加入同包双手反馈与SDK成功提交目标、capture身份、原始时间与context证据。身体、完整IK、19关节反馈、底盘、相机原有解析继续使用；保存转换模型和代码哈希。
4. **HDF5→LeRobot**：读取同一HDF5的身体和双手，填满统一78维中实际采集的76维，严格校验时间与mask。完整频率的replay资料另外保留，不用20Hz训练向量代替原始控制流。
5. **统一入口及读取**：`convert_unified`顺序调用三阶段，固定每个任务的配置副本；提供LeRobot v2.1读取适配，解决保留原编号后的时序窗口索引。

主机项目根：`/home/descfly/apex_n_sharpa`。有效数据及配置根：`/mnt/apex-data/apex_n_sharpa/data`。新配置为`config/apex_unified78.json`和`config/lerobot_unified78.json`，保留旧默认配置供旧数据读取。

## 固定78维布局

以下均为零起始、左闭右开区间；observation.state、action、validity的最后一维始终为78。

| 槽位 | 数据 | 有效性 |
|---|---|---|
| 0:9 | 左末端XYZ + 旋转矩阵前两列 | 1 |
| 9:18 | 右末端XYZ + 旋转矩阵前两列 | 1 |
| 18:27 | 头部eyes_link末端姿态 | 1 |
| 27:32 | waist_joint_1/2/3、Head_J1_Joint、Head_J2_Joint | 1 |
| 32:54 | 左手22关节 | 1 |
| 54 | 左夹爪保留槽位，填0 | **0** |
| 55:77 | 右手22关节，位置不前移 | 1 |
| 77 | 右夹爪保留槽位，填0 | **0** |

身体第一个关节单位m，其余四个为rad；双手单位rad。state使用反馈；身体action使用身体/头部控制器目标，双手action只使用带SDK成功提交证据的目标。这不等于机械关节已到位。归一化和loss必须依据validity/action_mask排除54和77，不能删除这两个槽位。

## 时间对齐与replay保留

- 身体和双手的训练基准均为**机器人MCAP log_time**，int64纳秒，clock_domain=robot_receive。手部header必须等于context记录的received_robot_ns，并核验接收至MCAP的排队时间。
- 手部源时间、机器人接收时间、session/seq、序列号、SDK结果单独保留。部署后只读时钟比较发现：机器人系统时间比av主机约慢35.45秒，SSH往返界限约±0.107秒。此次没有修改系统时钟。因此两台机器的源时间不能直接相减当作采样误差，必须使用共同的机器人MCAP时间轴。
- 在有效录制窗口和各数据流公共区间建立20Hz时间网格。action只取该时刻之前的目标，匹配上限50ms；启用字段缺失或任一帧不合格就拒绝导出，不静默截取另一段或压缩时间。
- 隔离验证已证明转换时钟选择和匹配规则一致；**尚未实测真实双手与机器人端到端延迟，不能宣称硬件同时采样**。下一次真实短录制仍需核验流间偏差、排队延迟和掉帧。
- HDF5保留原频率全19关节、完整IK及availability/seed、身体和头部目标、底盘反馈与命令、双手反馈和成功提交目标、原Raw文件、转换模型及来源证据。
- LeRobot的`meta/unified_replay.json`保留同一capture的原频率数据和整数纳秒时间，提供共同origin_ns、各流offset_ns和起始状态。`meta/source_timestamps.json`还保留20Hz对齐来源及native replay资料。
- 当前统一replay输出是**数据及时间计划**，没有实现或执行全身+双手联合物理回放器。旧replay客户端拒绝新的有效身体/手部槽位，不能把它当作新版执行器。

## 使用入口

在av-pipeline主机上，完成并停止录制后执行（3是部署后预计的首个新编号，实际以录制返回值为准）：

```bash
cd /home/descfly/apex_n_sharpa
./convert_unified --task my_capture --episode 3
```

默认从机器人`user@6.6.7.100:/home/user/gento_replay_bags`导入，仅处理指定episode，随后生成对应HDF5与LeRobot。命令不启动录制、不初始化设备、不发送控制命令。再次运行相同命令会校验后复用已完成结果。

仅转换已导入Raw：

```bash
./convert_unified --task my_capture --episode 3 --skip-import
```

允许通过`--apex-config`和`--lerobot-config`选择明确的unified78配置。入口会将有效配置固定到`data/config/unified_runs/<task>/`。同一任务改变配置会拒绝执行；需要新任务名。单独运行底层转换器时应使用该任务的固定配置，避免因为配置文件字节不同而触发来源一致性校验。

`--allow-diagnostic`仅供明确的模拟验收，会贯穿所有输出；正式转换和训练读取默认拒绝。中断导入保留`.episode_XXXXXXXX.partial`供检查，不自动覆盖。

## LeRobot读取适配

保持现有v2.1格式，验证使用`lerobot==0.3.3`。上游此版本默认枚举0到total_episodes-1，并用episode编号索引连续时序边界数组；单独保存原42号episode需要适配。依据：[上游LeRobotDataset源码](https://github.com/huggingface/lerobot/blob/v0.3.3/src/lerobot/datasets/lerobot_dataset.py)。

已增加`src/unified_lerobot.py`和`src/original_episode_index.py`，仅将时序边界查找映射为内存位置，磁盘和返回样本中的episode_index不变。使用有上述LeRobot依赖的训练环境：

```python
import sys
sys.path.insert(0, '/home/descfly/apex_n_sharpa/src')
from unified_lerobot import load_episode

dataset = load_episode(
    '/mnt/apex-data/apex_n_sharpa/data/lerobot/my_capture/episode_00000003',
    delta_timestamps={'action': [0.0, 0.05, 0.10]},
)
```

本轮仅在外置盘独立验证环境`/mnt/apex-data/apex_n_sharpa/validation/lerobot033-venv`安装训练依赖，公共转换虚拟环境保持原样。未宣称任意版本LeRobot或任意训练代码无需适配即可使用；训练代码仍须使用夹爪mask。
